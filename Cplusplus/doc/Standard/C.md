# 缓冲区溢出高危函数

在 C 语言编程中，有几类函数如果不谨慎使用，很容易成为缓冲区溢出漏洞的根源。这通常是因为它们缺乏对写入操作边界的必要检查。了解这些函数及其潜在风险是编写安全代码的第一步。

## 1. 常见高危函数列表

以下表格按照功能分类，列出了最常与缓冲区溢出相关的C标准库函数，并总结了其风险和基本的改进思路。

| 分类                | 高危函数                                               | 主要风险                                                     | 基本改进思路                                                 |
| :------------------ | :----------------------------------------------------- | :----------------------------------------------------------- | :----------------------------------------------------------- |
| **字符串操作**      | `gets()`                                               | 从`stdin`读取，**无法**限制输入长度，是造成缓冲区溢出的最危险函数之一。 | **永远不要使用**。完全替代为 `fgets()`。                     |
|                     | `strcpy()`                                             | 将源字符串复制到目标缓冲区，**不检查**目标缓冲区大小。       | 使用 `strncpy()`、`strlcpy()`(非标准) 或 `strcpy_s()`(C11 Annex K)。 |
|                     | `strcat()`                                             | 将源字符串追加到目标缓冲区末尾，**不检查**目标缓冲区剩余空间。 | 使用 `strncat()`、`strlcat()`(非标准) 或 `strcat_s()`(C11 Annex K)。 |
|                     | `sprintf()` / `vsprintf()`                             | 将格式化数据写入字符串，**不检查**目标缓冲区大小。           | 使用 `snprintf()` 或 `vsnprintf()`。                         |
|                     | `strtok()`                                             | 内部使用静态变量，非线程安全，且可能因不当使用导致越界。     | 使用线程安全的 `strtok_r()` (POSIX) 或 `strsep()`。          |
|                     | `strlen()`                                             | 依赖 `NULL` 结尾，如果源字符串缺少结尾符，会导致越界读取。   | 在确定字符串由 `NULL` 结尾前，避免使用。可使用 `strnlen_s()`。 |
| **格式化输入/输出** | `scanf()` 系列<br>(`scanf`, `fscanf`, `sscanf` 等)     | 使用 `%s` 格式说明符时，如果不指定宽度，会写入到任意长度的缓冲区。 | 指定最大字段宽度（如 `%255s`），或使用 `fgets()` 读取后解析。 |
|                     | `printf()` 系列<br>(`printf`, `fprintf`, `sprintf` 等) | 当**格式字符串由用户控制**时，攻击者可以利用格式字符串漏洞读取或写入内存。 | 使用 `printf("%s", user_input)` 而不是 `printf(user_input)`。 |
| **内存操作**        | `memcpy()`                                             | 按指定字节数复制，**不检查**目标和源缓冲区实际大小，可能覆盖目标区域外的内存。 | 确保复制的字节数不超过目标缓冲区大小，或使用 `memcpy_s()`(C11 Annex K)。 |
| **文件/IO操作**     | `getwd()`                                              | 获取当前工作目录，但**不检查**目标缓冲区大小，可能导致溢出。`getcwd()` 更安全。 | 使用 `getcwd()`。                                            |
|                     | `realpath()`                                           | 将相对路径转为绝对路径，如果提供的缓冲区过小，可能溢出。     | 使用 `realpath()` 时确保缓冲区大小为 `PATH_MAX`，或使用 `realpath()` 的 GNU 扩展变体。 |
| **其他**            | `alloca()`                                             | 在栈上动态分配内存。分配大小过大或循环中使用会导致栈溢出。   | 对于大尺寸或不可预测的尺寸，改用 `malloc()`/`calloc()`。     |
|                     | `atoi()` 系列<br>(`atoi`, `atol`, `atoll`)             | **不进行错误检查**，输入无效时会返回 `0` 或未定义行为，可能导致逻辑错误。 | 使用 `strtol()` / `strtoul()` 系列函数，它们能进行完善的错误检测。 |

## 2. 如何安全替代：选择正确的工具

简单地将一个不安全函数替换为所谓的“安全”函数（如`strncpy`）是不够的，必须**正确使用**。

*   **最佳实践**：使用 `snprintf`，并检查其返回值。
    ```c
    char buffer[10];
    // 保证 buffer 大小正确，并主动为结尾符预留空间
    int written = snprintf(buffer, sizeof(buffer), "%.*s", (int)sizeof(buffer)-1, long_string); 
    if (written < 0 || written >= sizeof(buffer)) {
        // 处理截断或错误
    }
    ```

*   **C11标准的安全替代 (`_s` 系列)**：C11标准引入了Annex K，定义了一系列边界检查接口，如`strcpy_s`, `strcat_s`, `sprintf_s`, `fopen_s`等。这些函数会在运行时检查边界，超出范围时会调用约束处理函数。
    *   **注意**：Annex K的实现并非完全普及，尤其是在Linux/Unix平台的支持度有限，在需要跨平台的代码中需谨慎考虑。

*   **特定平台的最佳选择**：除了ANSI C标准，不同平台提供了各自推荐的更安全的选择。
    *   **Unix/Linux (BSD)**: `strlcpy()`, `strlcat()`。这些函数旨在提供简单、可靠的边界检查和自动 `NUL` 结尾。
    *   **Microsoft Windows (MSVC)**: `strcpy_s`, `strcat_s`, `sprintf_s` 等 `_s` 系列。

*   **编译器辅助工具**：许多编译器提供了静态检查工具来帮助识别不安全函数。例如 `clang-tidy` 提供了 `bugprone-unsafe-functions` 检查。微软的 Visual Studio 在检测到不安全的 CRT 函数时会发出警告，并提示使用其安全的 `_s` 系列替代。

## 3. 核心原则

除了单纯依赖某个“安全”函数，更重要的是理解以下核心安全原则：

1.  **边界检查**：任何写入操作都必须明确知晓目标缓冲区的剩余大小，并确保写入不越界。
2.  **输入验证**：永远不要信任来自用户的任何输入。在操作前对输入数据的长度、格式和范围进行严格验证。
3.  **避免未被检查的复制**：像`gets`这样的函数在本质上就是危险的，应完全避免使用。

## 4. 总结

C语言的安全编程不是简单地机械替换函数，而在于始终贯彻边界检查和输入验证的思想。对于新项目，建议全面使用 `snprintf` 和 `strlcpy`/`strlcat`（如果可用），并考虑启用编译器的安全警告和静态分析工具。对于遗留代码，可以逐步替换高危函数，特别是 `gets()`。
