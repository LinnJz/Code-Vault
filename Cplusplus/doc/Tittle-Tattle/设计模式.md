## SOLID 原则简介

SOLID 是面向对象设计的五个基本原则，由 Robert C. Martin 提出。遵循这些原则可以提高代码的可维护性、可扩展性和可测试性。下面逐一解释并用 **C++17** 给出代码示例。

---

### 1. 单一职责原则 (SRP)

> **一个类应该只有一个引起它变化的原因**，即每个类只负责一项职责。

**含义**：一个类只做一件事，修改该类的原因只能有一个。如果一个类承担了多个职责，修改其中一个职责可能影响其他无关的功能。

**示例**：假设我们有一个`Report`类，既要生成报告内容，又要保存到文件。这违反了 SRP。应该拆分为两个类。

```cpp
#include <iostream>
#include <fstream>
#include <string>

// 职责1：生成报告内容
class ReportContent {
public:
    std::string generate() const {
        return "This is the report content.";
    }
};

// 职责2：保存报告到文件
class ReportSaver {
public:
    void saveToFile(const std::string& content, const std::string& filename) {
        std::ofstream file(filename);
        if (file.is_open()) {
            file << content;
            std::cout << "Report saved to " << filename << std::endl;
        } else {
            std::cerr << "Cannot open file." << std::endl;
        }
    }
};

// 使用
int main() {
    ReportContent contentMaker;
    std::string content = contentMaker.generate();

    ReportSaver saver;
    saver.saveToFile(content, "report.txt");
    return 0;
}
```

### 2. 开闭原则 (OCP)

> **软件实体（类、模块、函数等）应该对扩展开放，对修改关闭**。

**含义**：当需求变化时，应通过添加新代码来扩展行为，而不是修改已有的、经过测试的代码。通常通过抽象和多态实现。

**示例**：计算不同形状的面积。如果不使用 OCP，每次增加新形状都需要修改`AreaCalculator`中的`switch`或`if-else`。改进后使用基类虚函数。

```cpp
#include <iostream>
#include <vector>
#include <memory>

// 抽象基类
class Shape {
public:
    virtual double area() const = 0;
    virtual ~Shape() = default;
};

// 具体形状：矩形
class Rectangle : public Shape {
    double width, height;
public:
    Rectangle(double w, double h) : width(w), height(h) {}
    double area() const override {
        return width * height;
    }
};

// 具体形状：圆形
class Circle : public Shape {
    double radius;
public:
    Circle(double r) : radius(r) {}
    double area() const override {
        return 3.14159 * radius * radius;
    }
};

// 新增形状（扩展开放，无需修改原有计算逻辑）
class Triangle : public Shape {
    double base, height;
public:
    Triangle(double b, double h) : base(b), height(h) {}
    double area() const override {
        return 0.5 * base * height;
    }
};

// 计算总面积（对修改关闭，对扩展开放）
class AreaCalculator {
public:
    double totalArea(const std::vector<std::unique_ptr<Shape>>& shapes) const {
        double total = 0.0;
        for (const auto& shape : shapes) {
            total += shape->area();
        }
        return total;
    }
};

int main() {
    std::vector<std::unique_ptr<Shape>> shapes;
    shapes.push_back(std::make_unique<Rectangle>(5.0, 4.0));
    shapes.push_back(std::make_unique<Circle>(3.0));
    shapes.push_back(std::make_unique<Triangle>(2.0, 5.0));

    AreaCalculator calculator;
    std::cout << "Total area: " << calculator.totalArea(shapes) << std::endl;
    return 0;
}
```

### 3. 里氏替换原则 (LSP)

> **派生类必须能够替换其基类**，即任何使用基类的地方都可以透明地使用派生类，且不会改变程序的正确性。

**含义**：子类可以扩展父类的功能，但不能改变父类原有的语义。例如，子类重写方法时不能强化前置条件或弱化后置条件。

**示例**：一个经典的违反 LSP 的例子是`Rectangle`和`Square`。正方形是矩形的子类，但如果修改正方形的宽或高独立，就会破坏行为。更好的设计是使用抽象基类`Shape`，而不是强制继承关系。

```cpp
#include <iostream>

// 违反 LSP 的设计
class Rectangle {
protected:
    double width, height;
public:
    Rectangle(double w, double h) : width(w), height(h) {}
    virtual void setWidth(double w) { width = w; }
    virtual void setHeight(double h) { height = h; }
    double getWidth() const { return width; }
    double getHeight() const { return height; }
    double area() const { return width * height; }
};

class Square : public Rectangle {
public:
    Square(double side) : Rectangle(side, side) {}
    void setWidth(double w) override { width = w; height = w; }
    void setHeight(double h) override { width = h; height = h; }
};

// 下面的函数如果传入 Square 就会产生意外结果（改变宽同时改变了高）
void resizeRectangle(Rectangle& rect, double newWidth, double newHeight) {
    rect.setWidth(newWidth);
    rect.setHeight(newHeight);
    // 期望面积 = newWidth * newHeight，但对于 Square 会变成 newHeight * newHeight
}

// 符合 LSP 的改进：避免正方形继承矩形，使用抽象 Shape
class Shape {
public:
    virtual double area() const = 0;
    virtual ~Shape() = default;
};

class GoodRectangle : public Shape {
    double width, height;
public:
    GoodRectangle(double w, double h) : width(w), height(h) {}
    double area() const override { return width * height; }
    // 可以单独提供设置宽高的方法，但不影响替换性
};

class GoodSquare : public Shape {
    double side;
public:
    GoodSquare(double s) : side(s) {}
    double area() const override { return side * side; }
};

int main() {
    // 违反 LSP 的调用
    Rectangle rect(5, 4);
    Square square(4);
    resizeRectangle(rect, 6, 3);   // 正确，面积 = 18
    resizeRectangle(square, 6, 3); // 错误：面积变成 9，但调用者期望 18
    std::cout << "Square area after resize: " << square.area() << std::endl;

    // 符合 LSP 的设计：不把 Square 当作 Rectangle 使用，直接使用 Shape
    GoodRectangle goodRect(5, 4);
    GoodSquare goodSquare(4);
    // 不再有替换问题
    return 0;
}
```

> **实际开发中**：LSP 要求子类的行为不能违背基类约定的行为，通常需要避免继承那些会改变基本行为的关系。

### 4. 接口隔离原则 (ISP)

> **不应该强迫客户依赖它们不使用的接口**。即多个专门的接口要好于一个胖接口。

**含义**：如果一个接口包含太多方法，实现它的类必须实现所有方法，即使有些方法不需要。应该将大接口拆分为更小、更具体的接口。

**示例**：打印机系统，有些机器只能打印，有些能打印+扫描，有些能打印+扫描+传真。使用多个小接口。

```cpp
#include <iostream>
#include <memory>

// 拆分接口
class IPrinter {
public:
    virtual void print(const std::string& content) = 0;
    virtual ~IPrinter() = default;
};

class IScanner {
public:
    virtual void scan() = 0;
    virtual ~IScanner() = default;
};

class IFax {
public:
    virtual void fax() = 0;
    virtual ~IFax() = default;
};

// 简单打印机：只实现 IPrinter
class SimplePrinter : public IPrinter {
public:
    void print(const std::string& content) override {
        std::cout << "Printing: " << content << std::endl;
    }
};

// 多功能机：实现多个接口
class MultiFunctionMachine : public IPrinter, public IScanner, public IFax {
public:
    void print(const std::string& content) override {
        std::cout << "Printing: " << content << std::endl;
    }
    void scan() override {
        std::cout << "Scanning document" << std::endl;
    }
    void fax() override {
        std::cout << "Sending fax" << std::endl;
    }
};

// 使用
void doPrint(IPrinter& printer) {
    printer.print("Hello, ISP!");
}

int main() {
    SimplePrinter printer;
    doPrint(printer);

    MultiFunctionMachine mfp;
    doPrint(mfp);  // 只依赖 IPrinter 接口，不需要实现扫描/传真
    return 0;
}
```

### 5. 依赖倒置原则 (DIP)

> **高层模块不应该依赖低层模块，二者都应依赖抽象；抽象不应该依赖细节，细节应该依赖抽象**。

**含义**：要面向接口编程，而不是面向实现编程。通过依赖注入等方式解耦。

**示例**：一个`NotificationService`高层类需要发送消息，它应该依赖`IMessageSender`抽象接口，而不是直接依赖`EmailSender`或`SMSSender`具体类。

```cpp
#include <iostream>
#include <memory>

// 抽象接口
class IMessageSender {
public:
    virtual void send(const std::string& message) = 0;
    virtual ~IMessageSender() = default;
};

// 低层模块：邮件发送器
class EmailSender : public IMessageSender {
public:
    void send(const std::string& message) override {
        std::cout << "Sending email: " << message << std::endl;
    }
};

// 低层模块：短信发送器
class SMSSender : public IMessageSender {
public:
    void send(const std::string& message) override {
        std::cout << "Sending SMS: " << message << std::endl;
    }
};

// 高层模块：通知服务，依赖抽象 IMessageSender
class NotificationService {
    std::unique_ptr<IMessageSender> sender;
public:
    // 通过构造函数注入依赖（依赖倒置）
    explicit NotificationService(std::unique_ptr<IMessageSender> s) : sender(std::move(s)) {}

    void notify(const std::string& message) {
        sender->send(message);
    }
};

int main() {
    // 使用邮件发送
    auto emailSender = std::make_unique<EmailSender>();
    NotificationService emailNotif(std::move(emailSender));
    emailNotif.notify("Hello via email");

    // 轻松切换到短信发送，无需修改 NotificationService
    auto smsSender = std::make_unique<SMSSender>();
    NotificationService smsNotif(std::move(smsSender));
    smsNotif.notify("Hello via SMS");

    return 0;
}
```

## 总结

| 原则 | 英文                  | 核心思想               |
| ---- | --------------------- | ---------------------- |
| S    | Single Responsibility | 一个类只负责一个职责   |
| O    | Open/Closed           | 对扩展开放，对修改关闭 |
| L    | Liskov Substitution   | 子类型必须能替换基类型 |
| I    | Interface Segregation | 接口应该小而专一       |
| D    | Dependency Inversion  | 依赖抽象，而非具体实现 |

C++17 中的智能指针 (`std::unique_ptr`)、`override` 关键字、纯虚函数等特性可以帮助更好地实现这些原则。实际开发中灵活运用 SOLID 原则，可以显著提升代码质量。
